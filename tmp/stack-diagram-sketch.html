Desktop flow

herdr and Zed as equal-height panels side by side, mirroring the two Mac workspaces you swipe between. Two sandboxes: one running the workflow, one running the cross review it spawned.

What changed

  • Zed is now a full-height panel beside herdr rather than a small box above it. Equal heights and a single gap between them is the part that mirrors the swipe — they read as two workspaces, not as a hierarchy.
  • The two sandboxes are now one workflow and its cross review, labelled sbx /dev-workflow and sbx /pr-review. The red edge between them stops being an abstract capability and becomes the specific thing that produced the second box.
  • The per-sandbox egress arrows collapsed into one from herdr. With Zed on the right there was no clean margin for a riser, and one arrow out of herdr says the same thing — the agents inside it reach GitHub. Three parallel verticals now, one per path.

Two calls I made that you should check

  • I dropped subagents from the review sandbox. Your explainer describes /pr-review as review-only, posting a comment and never fixing — so it read as single-agent next to the six subagent definitions /dev-workflow uses. Easy to add back if it does spawn them.
  • The skill name now appears twice per sandbox — once on the container, once as a chip. You asked for both, so I kept both, but the container label alone would carry it: sbx /dev-workflow holding Claude Code → subagents, and sbx /pr-review holding just Codex. That drops two chips and makes the review sandbox visibly lighter than the workflow one, which is accurate.

Carried forward to the mobile pass

  • Side-by-side panels are the first thing to break. Stacked, herdr above Zed loses the swipe metaphor — worth deciding whether mobile keeps Zed at all, since the mobile story in the post is herdr and the GitHub app.
  • The three-chip row inside the workflow sandbox is the next thing to overflow.
  • The ssh edge turns vertical once the devices stack, which reads better than it does here.

Hub on top, two devices below

GitHub as the bar everything converges on. Underneath it, only two top-level boxes — the two devices — and their separate paths up to the work.

What this shape says that the arrow list can't

  • GitHub is a hub, not a terminus. The list ends there as if it were the bottom of the stack. Putting it on top as a bar makes the convergence the first thing a reader sees, and it's the honest picture: it's the one thing both devices reach directly.
  • Two devices, not one chain. The top level is now a claim about your setup rather than a sequence — this is a workflow that lives on two devices and follows you between them. That reads in about a second.
  • Zed is a sibling of herdr. It sits on the laptop beside herdr with its own path to GitHub. It's absent from the arrow list entirely, despite being what the whole opening section is about.
  • Multiplexing is a cardinality, not a layer. Stacked sandboxes inside herdr say "several at once" structurally, where a linear list has to say it in a caption.
  • Cross-family review is a lateral edge, and status hooks flow back up. Neither has any representation in a list where every arrow points the same way.

How it could work as the recurring marker

  • The nesting still encodes your outward walk — the work → agent → sandbox → herdr → the way in — it's just read inside-out rather than top-down. So the progressive-highlight idea survives: dim everything, light up the sandbox interior first, then the sandbox boundary, then herdr, then the phone and the ssh edge.
  • The GitHub bar stays lit the whole way through. That's a feature — it's the one element that's true at every stage, and it keeps reminding the reader where all of this is headed while you walk them out.
  • At small widths this degrades better than the nested rings did: the bar stays, and the two devices stack vertically instead of shrinking.
